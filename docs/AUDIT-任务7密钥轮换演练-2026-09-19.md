## 三、演练暴露的问题与处置（教训）

1. **`nest build` 会直接覆盖 `apps/api/dist`**（生产产物）。演练时用源码补丁构建，导致生产 dist 一度带演练补丁；运行中的进程不受影响（代码已加载），但**重启即崩**（无密钥时抛错）。处置：用还原后的源码重建 dist，并校验 `演练补丁=0 / 回退逻辑=1`。
   → 生产执行改为**原子序列**：先停服务 → 再写密钥 → 改源码 → 构建 → 重加密 → 启动。
2. **后台实例需按 PID 终止**：环境变量不出现在命令行，`pkill -f 'APP_PORT=4197'` 匹配不到，导致演练库 `DROP` 报 `being accessed by other users`。处置：按 PID 精确终止，并核对生产 PID 未受影响。
3. 演练脚本首轮构建/启动时序不可靠（`cp -r dist dist-keystest` 复制到不存在的目录 + 后台启动未轮询健康）。处置：改为"构建 → 复制 → 校验入口文件存在 → 启动 → 轮询健康（最长 36s）"。
