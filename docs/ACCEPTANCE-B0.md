## 八、B1 启动前置条件（真机联调 / 计费实现）

**必须由用户提供（Hermes 不能代做）**：

1. **平台凭证**：微信公众号 AppID/AppSecret、抖音开放平台 ClientKey/ClientSecret、小红书企业资质与审核结果；
2. **告警渠道**：邮件 SMTP 账号（或群机器人 webhook），用于 purge 完成、监控告警、登录爆破通知；
3. **异地备份账号**：对象存储（OSS/COS/S3）或另一台服务器，用于 purge 备份异地存放；
4. **业务决策**：SaaS 目标市场与获客路径、是否保留"最后工作区软保护"策略、是否需要平台级（跨工作区）管理员角色；
5. **联调窗口**：真机联调会产生真实平台调用（可能计费），需要用户指定时间窗与账号。

**工程侧已就绪**：OAuth 骨架与适配器接口、发布队列与重试、凭证加密存储、导出与 purge、配额与用量流水。

## 九、B2 启动前置条件（SaaS 化）

1. **定价模型**：套餐划分、超额单价、试用策略、年付折扣 —— 全部是业务决策（`plans` 表已留字段与占位说明）；
2. **目标市场与合规**：服务条款、隐私政策、数据处理协议（DPA）的**法务来源**；
3. **SLO 目标**：可用性、延迟、支持响应时间（决定监控阈值与值班安排）；
4. **支付渠道**：支付宝/微信/Stripe 商户号与密钥（实现 `PaymentProvider` 并注入即可）；
5. **租户开通流程**：自助注册、邮箱/短信验证、发票信息、退订与退款规则；
6. **数据导出与删除的对外承诺**：当前实现（工作区导出 + 合规删除 30 天）已可作为合同附件。

## 十、本阶段发现并修复的真实缺陷（摘要）

B0.4 第 5 步与 B0.8/B0.9 期间由演练与真机实测发现的缺陷（全部已修 + 已加断言）：

1. 备份表顺序（子表在前）导致 purge 恢复 **0 行** → 拆 `BACKUP_TABLES` 父表在前；
2. purge 完成通知写进刚被清除的工作区 → 改只走外部渠道；
3. 预检"消费者 ≤1"与"重启清理残留"互锁 → 只统计在跑的消费者；
4. 软删当前工作区后界面无路可走 → `GET /workspaces` 与 `switch-workspace` 状态豁免；
5. 设置缓存只按 key → 多工作区读到对方 AI 密钥；运行时快照进程单例 → A 改权限矩阵影响 B；
6. 平台字典全表读取 → 跨工作区数据串入；
7. **种子不建工作区成员行** → 全新安装管理员登录 403；
8. **部署层 `PUBLISH_WORKER_ENABLED=false` 在库未初始化时失效** → 双消费者；
9. E2E 硬编码生产默认工作区 id（种子 UUID 每次不同）；
10. compose 误读生产 `.env` 插值 → postgres 与 api 口令不一致（且会把生产密钥带进容器）；
11. 合规测试内容标题未带套件前缀 → 生产库残留 36 条（已清理并修规格）。
