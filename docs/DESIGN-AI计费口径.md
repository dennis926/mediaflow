# 设计：AI 计费口径（官方价 + 峰谷两档 + 官网自动抓取）

> 状态：已实现并上线（v0.3.1）。本文说明**为什么这样算**、边界在哪、官方改版时怎么应对。

## 1. 要解决的问题

改造前，全站只有一个固定价：输入 ￥2 / 缓存命中 ￥0.5 / 输出 ￥8（每百万 token）。三个后果：

1. **非工作时段费用虚高约 2 倍**。DeepSeek 分峰谷：高峰价是空闲价的 2 倍，而空闲时段覆盖了全部夜间、周末与法定节假日——正是批量跑内容的时段。
2. **缓存命中费用虚高约 12 倍**。官方空闲档缓存命中价是 ￥0.02，配置里写的是 ￥0.5。
3. **官方调价无人跟**。价格写死在设置里，官方改了只能靠人发现。

## 2. 计费口径

### 2.1 价格优先级（高 → 低）

| 层级 | 来源 | 存储位置 | 谁维护 |
| --- | --- | --- | --- |
| 1 | 用户手工覆盖价 | `system_settings.AI_MODEL_PRICES` | 人在「AI 用量 → 改价」 |
| 2 | **官网自动抓取价** | `AI_OFFICIAL_PRICES.providers` | 系统定时抓取（8 家） |
| 3 | **国内权威参考价**（国家超算互联网） | `AI_OFFICIAL_PRICES.domestic` | 系统定时抓取（人民币，兜底） |
| 4 | **聚合价目表**（models.dev） | `AI_OFFICIAL_PRICES.aggregate` | 系统定时抓取（美元，兜底） |
| 5 | 预置目录价 | 代码 `model-catalog.ts` | 随代码发布 |
| 6 | 全局兜底价 | `AI_PRICE_*` 三个设置项 | 老配置兼容 |

任何一层有可用价格，计费就不会算不出来。抓取失败只是"继续用上一份"，不会阻断。

**第 3、4 层为什么存在、又为什么必须排在官网价之后**：OpenAI（官网对本站出口 IP 返回 403）、MiniMax（价格由 JS 渲染）、豆包（人机校验）三家抓不到官网价，等于没有价格，需要一份公开价目表补上。两家兜底源的差别决定了它们的顺序：

- **国家超算互联网（SCNet，第 3 层）是人民币口径**，人民币进人民币出，不经过汇率这一层误差；它是科技部指导的国家级算力平台，公开刊例价，可抓 JSON 接口、无需鉴权。国内供应商抓不到官网价时，它比美元聚合价可靠。
- **models.dev（第 4 层）只有美元价、且把峰谷拍平成单档**——DeepSeek 官方高峰 ￥2/￥8，它给 0.15/0.6 美元（≈ 谷价）。若让它盖住官网价，高峰时段会按谷价计费，**少收一半**。

两层都只在官网抓取价缺失时才被读取，且**都不能覆盖官网价**。

### 2.2 峰谷判定

规则来自供应商官网原文（DeepSeek）：**北京时间周一至周五（不含法定节假日）09:00-12:00、14:00-18:00 为高峰；其余时段（含周末与节假日全天）为空闲。**

- 窗口与节假日写在 `AI_PEAK_WINDOWS`（JSON），可改，不用发版。
- 用 `Intl.DateTimeFormat` 按目标时区取日历分量，不手工算 UTC 偏移（避免时区/夏令时类错误）。
- 窗口右端是**开区间**（18:00 整已算空闲），与官网口径一致。
- 配置损坏时**一律按空闲算**：少算是显示误差，凭空造出高峰会让每一笔费用都虚高。

### 2.3 计费时刻

按**调用发生的那一刻**取档位（`costOf(..., { at })`），并把档位写进 `ai_generations.price_snapshot`：

```json
{ "provider": "deepseek", "model": "deepseek-flash",
  "price": { "input": 1, "output": 4, "cacheWrite": 1, "cacheRead": 0.02 },
  "source": "official", "tier": "offpeak", "tierLabel": "空闲时段" }
```

这样日后官方调价、或有人质疑"这笔为什么这么算"，都能拿出当时的档位与单价。

## 3. 官网抓取怎么做的

- **只信官网**：不采信第三方聚合站，因为一个错数字会污染全部历史费用。
- **零依赖解析**：`pricing/parse-utils.ts` 是容错表格解析器（HTML / Markdown / JSX 三种表格形态），够用且不引新依赖（AGENTS.md 禁止未批准依赖）。
- **容错而非猜**：页面改版时返回空数组，调用侧保留旧价并告警，**绝不猜一个数**。
- **抓取与计费解耦**：定时任务失败只写日志；计费始终有价格可用。

### 3.1 注册表架构

`pricing/scrapers.ts` 里是 `SCRAPERS: ScraperDefinition[]`，每项含 `provider` / `url` / `parse()` / 可选 `headers`。
新增一家供应商 = 加一个数组项 + 一个解析函数，`scrapeProvider()` 统一负责抓取、反爬识别与错误包装。

### 3.2 覆盖范围（v0.3.1）

| 供应商 | 币种 | 模型数 | 来源 |
| --- | --- | --- | --- |
| DeepSeek | CNY（峰谷两档） | 2 | `api-docs.deepseek.com` 定价页 |
| 智谱 GLM | CNY | 26 | `docs.bigmodel.cn` `.md` 端点 |
| Kimi | CNY | 4 | `platform.moonshot.cn` `.md` 端点 |
| xAI Grok | USD | 8 | `docs.x.ai` 定价页 |
| Anthropic | USD | 13 | `anthropic.com/pricing` |
| Google Vertex | USD | 8 | `cloud.google.com` 定价页 |
| 通义千问 | CNY | 112 | `help.aliyun.com` `.md` 端点 |
| 豆包（火山引擎） | CNY | — | 被反爬拦截，见下 |

> 界面上的「抓取」卡片另有两张**兜底源**卡片（不属官网抓取）：国内权威参考价（国家超算互联网）与聚合价目表（models.dev）。

抓不到的供应商分两类，都**照实说明**而不是显示成故障：

- **官网反爬/不可达**：OpenAI（Cloudflare 403）、MiniMax（纯 JS 渲染，HTML 无价格）、豆包（人机校验页）。前两家记在 `UNSCRAPABLE_REASONS`，界面显示「不支持自动抓取」+ 原因。
- **本次抓取失败**：豆包属于这类——它**配置了抓取器**，但请求被打回。这类必须在快照与界面上留痕（见 3.3），否则用户无法区分「没配」和「抓不到」。

### 3.3 聚合价目表（models.dev）——只做兜底

`pricing/models-dev.ts` 读取 <https://models.dev/api.json>（约 5MB，225 家供应商），
只保留**我们目录里存在**的模型，落进快照的 `aggregate` 层。实测覆盖 10 家、50 个模型。

它补上的正是官网抓不到的那三家（OpenAI 6 个、MiniMax 1 个、豆包 7 个），
也顺带给其余各家多一层兜底。

三个必须记住的边界：

1. **只有美元价（含 `-cn` 中国区条目，见 3.3c）**。国内供应商的官方人民币价被换算成美元，
   换算率与官方原文不一致（智谱 GLM-5.3 官方 ￥8/￥28，它给 1.4/4.4 美元 ≈ ￥9.8/￥30.8）。
   所以国内供应商只要官网能抓到，就必须用官网价；抓不到时，人民币口径的
   国内权威参考价（3.3b）优先于它。
2. **峰谷被拍平**。DeepSeek 只给一个价（≈ 空闲档）。这是它不能越级的硬理由。
3. **`tiers` 是长上下文加价，不是峰谷**。它用 `tiers` 表达「超过 N k token 后翻倍」，
   我们只取基础档并把阈值写进 `note`，避免用户误以为超长上下文也是这个价。

模型名匹配做三层（精确 → 规范化去日期戳 → 前缀）：聚合表写 `doubao-seed-2-1-pro-260628`，
我们写 `doubao-seed-2.1-pro`；它写 `glm-5.3`，我们写 `GLM-5.3`。匹配结果写进
`ScrapedPrice.catalogModel`，计费侧按它反查。

### 3.3b 国内权威参考价（国家超算互联网）——人民币兜底

`pricing/scnet.ts` 读取 <https://www.scnet.cn/acx/llm/api/console/model/landing>，
返回 JSON（`inputPrice` / `cachedPrice` / `outputPrice`，**元/百万 tokens**），无需鉴权。
只保留我们目录里存在的模型，落进快照的 `domestic` 层。

它为什么单独占一层而不是并进 `aggregate`：**币种不同**。`aggregate` 是美元，必须乘汇率；
`domestic` 是人民币，乘汇率会凭空翻 7 倍。分层的直接好处是——将来某个兜底源改口径，
不会静默把另一层的数字算错。

**已知边界**：公开接口只返回首页推荐的 4 个模型（DeepSeek-V4.1-Flash、Kimi-K3、
Qwen3.8-Flash、GLM-5.3），完整列表需登录。所以它的定位是「官网抓不到时的**首选**兜底」，
而不是全量价目表；抓不到时继续往下降级到 `aggregate`。

### 3.3c 中国区条目（`-cn`）是美元，不是人民币

models.dev 上国内厂商有**两套条目**：国际版与 `-cn` 中国区版。`MODELS_DEV_PROVIDERS`
优先指向 `-cn`（它对应厂商国内站点的报价，更贴近国内用户实际付费口径），
`MODELS_DEV_PROVIDERS_FALLBACK` 在 `-cn` 无可用模型时回落到国际版。

**这里踩过一个会少收 7 倍的坑**：`-cn` 后缀曾被理解成「人民币计价」，
于是 `currencyOfModelsDevProvider()` 对 `-cn` 返回 `CNY`、不乘汇率。
交叉验证后否证了这个理解——`-cn` 表示「中国区站点」，**cost 仍是美元**：

| 条目 | models.dev cost | ×7 | 官方价 | 结论 |
| --- | --- | --- | --- | --- |
| `minimax-cn` / MiniMax-M3 | 0.3 / 1.2 | ￥2.1 / ￥8.4 | ￥2.1 / ￥8.4 | 一致 |
| `moonshotai-cn` / kimi-k3 | 3 / 15 | ￥21 / ￥105 | ￥20 / ￥100 | 一致 |
| `alibaba-cn` / qwen3.8-max | 1.78 / 5.33 | ￥12.4 / ￥37.3 | ￥12 / ￥36（刊例） | 一致 |

修正后 `currencyOfModelsDevProvider()` **恒返回 `'USD'`**，`-cn` 只影响取哪套条目，
不影响币种。单测锁住这条（`domestic-pricing.spec.ts`）。

### 3.4 失败必须留痕

`recordFailure()` 对**从未成功抓取过**的供应商同样建档，记录 `error` / `failedAt` / `consecutiveFailures` / `failures[]`（最多 20 条），且 `fetchedAt` 保持空字符串——界面据此区分「从未成功」与「上次成功时间」。抓取成功后清空当前错误与失败计数，但**保留失败历史**：一次成功不该抹掉「这家曾经连续被拦截 6 次」。

失败**不推进** `fetchedAt`，也**不覆盖**上一份可用价格：价格的新鲜度必须真实，否则界面会显示一个骗人的新鲜度。

### 3.5 反爬与退避

- `isChallengePage()` 识别 SHA-256 工作量证明页、混淆 Cookie 脚本、纯 JS 外壳（既无 HTML 表格也无 Markdown 表格行），抛出明确原因而不是「页面结构变化」。
- 定时任务按供应商单独计连续失败次数，退避 `min(2^n × 间隔, 24h)`，避免激进重试导致 IP 被永久封禁。
- **退避必须真的跳过请求**，只把时长写进日志等于没有退避。这里踩过一次：早期实现只在日志里
  打印「N 分钟内不再重试」，请求照发，结果豆包的连续失败一路涨到 4 次仍在每轮重试。
  现在 `refreshAllOfficialPrices(skip)` 接收退避中的供应商清单并跳过；被跳过的**不计入失败**
  （它不是「这次失败了」，而是「这次故意没打」）。

### 3.6 解析器踩到的坑（已用单测锁住）

- **DeepSeek 的 colspan**：官网表格第一行计费维度（`百万tokens输入（缓存命中）`）因 `colspan` 与「空闲时段」同行，天真的解析器会把**空闲档整行丢掉**，只剩高峰价——即夜间费用虚高一倍。解析逻辑是「扫整行找维度标签、扫整行找档位标签、值从档位标签之后取」，而不是按固定列号取。
- **Google 要英文页**：带 `Accept-Language: zh-CN` 时表头被翻译成中文，解析器匹配不上。抓取定义里固定 `en-US`。
- **Anthropic 的 `Prompt caching` 分组标签**没有价格，跨标签贪婪匹配会吞掉相邻的 Read 价，必须按 `__priceLabel` 切分。
- **阿里云的 JSX 表格**：`<td style={{...}}>` 里的 `>` 会让朴素正则断开，且用 `rowSpan`/`colSpan` 表达合并单元格；必须先展开成完整网格，再按「华北2（北京）」Tab 过滤（新加坡区价格约高 25%）。

## 4. 界面

- 顶部显示当前时段徽标（高峰/空闲）+ 高峰窗口说明 + 「立即抓取官网价」按钮。
- 模型价目表：分峰谷的供应商显示 `官方 峰 ￥2 / 谷 ￥1（当前 ￥1）`，一眼看清现在按哪档算。
- 「改价」弹窗对分峰谷的模型直接展示两档人民币价，一键填回取当前档。

## 5. 扩展新供应商

1. 在 `pricing/scrapers.ts` 写一个 `parseXxx(html)` 解析函数（优先找该家的 `.md` 端点，Markdown 表格比 HTML 稳定得多）。
2. 在 `SCRAPERS` 数组加一项：`{ provider, url, parse, headers? }`。
3. 在 `model-catalog.ts` 的 `SCRAPABLE_PROVIDERS` 加该 provider，并补上目录价（抓取失败时的兜底）。
4. 抓不到的把原因写进 `UNSCRAPABLE_REASONS`，界面会照实显示而不是报故障。
5. 若该供应商也分峰谷，只需在 `AI_PEAK_WINDOWS` 里按它的口径配窗口（或为它单独加窗口配置）。
6. 加解析器单测：把官网真实页面片段存进测试文件，锁住本次的解析行为。

只加聚合兜底（不写官网解析器）时更简单：在 `pricing/models-dev.ts` 的
`MODELS_DEV_PROVIDERS` 加一行「我们的 provider → models.dev 的 provider id」，
再在 `model-catalog.ts` 补上该供应商与它的模型即可——聚合表按目录模型 id 匹配，
目录里没有的模型会被自动忽略。

## 6. 待办与边界

- **OpenAI / MiniMax / 豆包抓不到官网价**：分别因 Cloudflare 403、JS 渲染、人机校验。三家已由兜底源补上价格，不再是「没有价格」；豆包的官网解析器已用保存下来的页面验证正确（10 个模型），等限流冷却即可自动恢复成官网价。
- **兜底源都可能滞后**：国家超算互联网是平台转售刊例价、models.dev 是第三方聚合表，调价后都不一定与官网同步。国内供应商优先用官网价、其次人民币权威价，海外只能用它 + 人工覆盖价兜底。
- **国家超算互联网公开接口只有 4 个模型**：完整列表需登录，未接。它是「首选兜底」而非全量价目表。
- **未做价格变动告警**：抓到涨价时不会主动通知，当前靠界面上的抓取时间与来源自查。
- **节假日列表需人工维护**（`AI_PEAK_WINDOWS.holidays`）；法定节假日每年不同，不硬编码在代码里。
- **海外供应商的峰谷**：目前只对国内供应商（官网明确分峰谷的，如 DeepSeek）按两档计费；海外供应商取同一档价。
