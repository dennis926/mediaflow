# 技术债：purge 备份异地存储（B0.4）

- 记录日期：2026-09-19
- 关联：`docs/DESIGN-多租户生命周期.md` §7/§12
- 等级：**中**（不阻塞 B0.4 上线，但对外 SaaS 前必须解决）

## 一、问题

工作区永久清除（purge）前的独立备份，是这次操作**唯一的后悔药**。用户要求它"不能与数据库同机存放"，
但本服务器目前**没有任何异地对象存储**，因此当下的实现是：

| 项 | 现状 |
| --- | --- |
| 存储路径 | `/www/backup/mediaflow/purge/{workspaceId}/{YYYYMMDD-HHMMSS}.sql.gz` |
| 是否异地 | **否 —— 与 PostgreSQL 在同一块盘（/dev/vda2）** |
| 保留 | 180 天（`WORKSPACE_PURGE_BACKUP_RETENTION_DAYS`） |
| 命名 | 含 workspaceId + 时间戳 + sha256 前 12 位；完整 sha256 记入 `workspace_purge_batches.backup_sha256` |

**风险**：磁盘故障、误删目录、勒索软件等同一故障域内的事件会**同时**带走数据库与这份后悔药。
换句话说：现在这个备份能抵御"误操作 purge"，但抵御不了"整机损毁"。

## 二、已有缓解

1. 备份与数据库虽同机但**不同目录**，且权限 600、不参与 site-backup 的导出集合（避免被 30G 级别的整站备份逻辑覆盖或误删）；
2. purge 前备份若失败（命令非 0 退出 / `gzip -t` 校验失败 / 磁盘空间不足），**purge 立即中止**——不会出现"没备份就删"的情况；
3. 每日整站备份（site-backup-manager，含 `/www/wwwroot` 与数据库）另有**百度网盘异地副本**，可覆盖大部分场景；
   但注意：它**不包含** purge 备份目录，故不能替代本项。

## 三、解决方案（择一，建议 1）

| 方案 | 做法 | 成本 | 建议 |
| --- | --- | --- | --- |
| 1. 对象存储 | 复用 site-backup-manager 已配置的**百度网盘**（或新开阿里云 OSS/COS）：purge 后先上传、校验 sha256、成功后再删本地 | 低（已有凭据体系） | ✅ 首选 |
| 2. 独立磁盘/分区 | 挂一块独立盘或独立分区挂到 `/www/backup-remote` | 需购盘 | 可选 |
| 3. 另一台服务器 | 通过 SSH/rsync 推到用户已有的其他节点（如 hm.hons.fun / d.hons.fun） | 低 | 可选（需密钥管理） |

## 四、解决后的验收标准

1. purge 备份生成后**立即**上传异地，并**用 sha256 校验**上传结果；
2. 校验通过才允许删除本地副本（保留期策略随之调整：异地 180 天，本地可缩到 7 天以省磁盘）；
3. 清理任务（180 天）同时删异地与本地，并写审计 `workspace.purge_backup_expired`；
4. 演练：从异地副本完整恢复一个工作区到临时库，验证数据可用（写入 `RUNBOOK-purge演练.md`）。

## 五、触发时机

- 对外 SaaS 开放注册前（阶段 C 之前）**必须**解决；
- 若在此之前需要执行 purge 且数据敏感度较高，改为：先手工把备份文件下载到本地/异地，再执行 purge。
